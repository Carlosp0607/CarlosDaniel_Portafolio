LexDoc: Sistema de gestión legal

prestación de servicios

Plataforma para la gestión de casos y documentos de un despacho jurídico, desarrollada en prestación de servicios para Turizo Lawyers Enterprise S.A. Tres perfiles con permisos diferenciados (administrador, jefe de firma y abogado), donde cada abogado accede únicamente a los casos que le fueron asignados. Incluye carga de documentos y alertas automáticas antes y después del vencimiento de plazos procesales. El aislamiento entre abogados está cubierto por pruebas automatizadas en pytest.

La demo enlazada usa datos ficticios.

Don Parqueo: SaaS para parqueaderos

demo en vivo

Sistema multiempresa para la operación diaria de parqueaderos. Varias empresas cliente trabajan sobre la misma base de datos con aislamiento total de su información: ninguna consulta devuelve registros de otra empresa. Cubre ingreso y salida de vehículos con cálculo de tarifa por minuto, hora o día, turnos de caja con cuadre por método de pago, mensualidades y reportes exportables a Excel. El cobro se ejecuta dentro de una transacción SQL con bloqueo del registro, y las reglas de cobro y de acceso están cubiertas por pruebas con pytest que corren en cada cambio mediante GitHub Actions.

Botón "Entrar como invitado": modo de solo lectura con datos ficticios.

Citas Consultorio: API de citas médicas con IA

demo en vivo

API REST para agendar citas en un consultorio con varias especialidades, con una página web para crear, ver, editar y eliminar citas. El paciente describe su motivo y un modelo de lenguaje vía OpenRouter sugiere la especialidad; si el servicio falla, la cita se crea igual con Medicina general. Los datos se validan con Pydantic y la regla de una cita por hora se garantiza con un índice único en PostgreSQL. Pruebas con pytest en cada cambio mediante GitHub Actions.

Mesa de Ayuda: Tickets de soporte y análisis de indicadores

demo en vivo

API de soporte técnico que registra incidentes y requerimientos con prioridad, controla el ciclo de vida del ticket (abierto, en proceso, escalado, cerrado) y escala del nivel 1 al nivel 2. Calcula el SLA de cada caso según su prioridad, exige documentar la solución para cerrar y sugiere soluciones desde una base de conocimiento. Los indicadores se calculan con SQL: porcentaje de SLA cumplido, horas promedio de solución, tasa de escalamiento y problemas más repetidos, y se exportan a CSV.

Los datos del análisis son tickets simulados.
